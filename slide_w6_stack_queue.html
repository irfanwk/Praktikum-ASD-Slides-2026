The Why & Aturan Lab • 6.2 Dasar Teori

Mengapa Membatasi Akses? & Standar C++ Prosedural

Pada Modul 3–5 kita membuat list bebas. Membatasi akses pintu masuk dan keluar bukan kelemahan, melainkan kontrak integritas.

🛡️ Mengapa Akses Perlu Dibatasi?

Jika sembarang fungsi boleh menyisipkan atau menghapus data di tengah-tengah urutan, alur sistem menjadi tidak terprediksi:

  • Undo/Redo & Call Stack memori: Hanya aksi paling akhir yang boleh dibatalkan. Mengambil dari tengah akan merusak rantai eksekusi.
  • Print Queue & Packet Router: Siapa yang datang duluan wajib dilayani duluan demi keadilan (*fairness*).

⚙️ Prosedural (Yang Dipakai) vs OOP (Bukan Ini)

Aspek Prosedural (Lab) OOP (Dilarang)
Wadah data struct publik class private
Operasi fungsi bebas di luar method di dalam class
Pemanggilan Push(S, x) S.push(x)
Mutasi state parameter referensi & this tersirat
Tiga Aturan yang Mengikat di Praktikum Ini:
  1. Semua data disimpan dalam struct. Tidak ada variabel global selain penghitung allocation balance.
  2. Setiap fungsi yang mengubah struktur menerimanya sebagai parameter referensi (&). Yang hanya membaca memakai const &.
  3. Setiap operasi yang punya prasyarat mengembalikan bool: true bila berhasil, false bila gagal. Jangan memakai exit()!
Mental Model • 6.2 Dasar Teori

Analogi Fisik: Tumpukan Piring vs Antrean Kasir

Kunci membedakan Stack dan Queue terletak pada berapa banyak ujung yang aktif disentuh.

Stack • LIFO 🍽️

Tumpukan Piring Kantin

Petugas kantin menaruh piring bersih yang baru dicuci di paling atas (Push). Mahasiswa yang ingin makan juga mengambil piring dari paling atas (Pop). Piring yang pertama kali ditaruh di dasar akan menjadi yang paling terakhir diambil.

1 Ujung Aktif: Masuk di ATAS, keluar di ATAS. Indeks kerja: nef - 1.
Queue • FIFO 🛒

Antrean Kasir Supermarket

Pelanggan baru datang dan berdiri di posisi paling belakang (Enqueue). Kasir melayani dan memproses pelanggan yang berdiri di paling depan (Dequeue). Tidak boleh memotong antrean dari tengah maupun dari depan.

2 Ujung Aktif: Masuk di BELAKANG (Rear), keluar di DEPAN (Front).
⚡ Perbedaan Tunggal yang Berdampak Besar: Pada stack, penambahan dan pengurangan terjadi di titik yang sama. Pada queue, penambahan dan pengurangan terjadi di dua ujung terpisah. Hal ini menuntut strategi implementasi yang sama sekali berbeda pada array!

ADT Stack: Spesifikasi & Representasi Array

Cukup satu array dan satu nef. Elemen teratas selalu di indeks nef - 1.

Operasi C++ Maksud Operasi Prasyarat Hasil / State Akhir
Push(S, x) Menambah nilai x di atas Stack tidak penuh* x jadi teratas baru, return true
Pop(S, x) Mengambil & membuang teratas Stack tidak kosong Nilai keluar lewat referensi x, nef berkurang 1
Top(S, x) Melihat teratas tanpa membuang Stack tidak kosong x terisi nilai teratas, stack TIDAK berubah
stack_a.cpp O(1) Semua Operasi 
const int KAP = 5; // kapasitas sengaja 5 agar mudah diuji
struct stack_a { int a[KAP]; int nef; };

bool SPush(stack_a &S, int x) {
    if (S.nef == KAP) return false; // PRASYARAT
    S.a[S.nef] = x; S.nef++;
    return true;
}

bool SPop(stack_a &S, int &x) {
    if (S.nef == 0) return false;   // PRASYARAT
    S.nef--; x = S.a[S.nef];         // nef turun DULU!
    return true;
}

🔍 Trace Masuk 7, 10, 4 lalu Pop:

  1. Mula-mula nef = 0.
  2. Push 7 → a[0]=7, nef=1.
  3. Push 10 → a[1]=10, nef=2.
  4. Push 4 → a[2]=4, nef=3 (Top di a[2]).
  5. Pop → nef turun ke 2 dulu, lalu a[2] dibaca ke x=4. Nilai 4 di RAM tidak dihapus secara fisik!

Stack dengan Linked List: Mengapa Selalu di Ujung Depan?

Tanpa batasan kapasitas tetap. Cukup memegang satu pointer atas yang berperan sama persis dengan head.

stack_list.cpp Tanpa Batas Penuh 
struct stack_l {
    node_t *atas; // menunjuk node teratas di head
    int nef;
};

void LPush(stack_l &S, int x) {
    node_t *b = new node_t;
    b->data = x;
    b->next = S.atas; // sambung dulu ke sisa stack
    S.atas = b;       // baru pindahkan pointer atas
    S.nef++;
}

bool LPop(stack_l &S, int &x) {
    if (S.atas == nullptr) return false;
    node_t *m = S.atas;
    x = m->data;
    S.atas = m->next; // pointer atas mundur DULU
    delete m;         // baru node lama dibebaskan
    S.nef--;
    return true;
}

ADT Queue & Mengapa Percobaan Pertama (Naif) Gagal

Queue menyentuh dua ujung berbeda: masuk di rear, keluar di front. Akibatnya pada array: kasus kotak mati.

$ ./queue_naif (Kapasitas = 5) Kotak Mati Permanen 
masuk 10 : [10  .   .   .   . ] front=0 rear=1 nef=1
masuk 20 : [10 20   .   .   . ] front=0 rear=2 nef=2
masuk 30 : [10 20  30   .   . ] front=0 rear=3 nef=3
keluar   : [ . 20  30   .   . ] front=1 rear=3 nef=2
keluar   : [ .  .  30   .   . ] front=2 rear=3 nef=1
masuk 40 : [ .  .  30  40   . ] front=2 rear=4 nef=2
masuk 50 : [ .  .  30  40  50 ] front=2 rear=5 nef=3
masuk 60 : [ .  .  30  40  50 ] DITOLAK: dikira PENUH!
Paradoks: Kapasitas array adalah 5. Yang sedang terisi hanya 3 (indeks 2, 3, 4). Tapi masukan 60 ditolak karena rear == KAP!

Mengapa Hal Ini Terjadi?

Pointer front dan rear hanya bisa MAJU. Setiap kali elemen dikeluarkan (Dequeue), front maju dan meninggalkan kotak kosong di belakangnya yang tidak pernah bisa dipakai lagi!

⛔ Jalan Keluar yang Salah: Menggeser!
Sebagian mahasiswa menggeser seluruh elemen ke kiri tiap kali Dequeue. Itu sah, namun membuat Dequeue menjadi O(N). Kita ingin solusi yang tetap O(1)!

Array Melingkar (Modulo) & Membedakan Penuh vs Kosong

Sambungkan kotak terakhir kembali ke kotak pertama via operator modulo % KAP.

queue_circular.cpp rear Dihitung, Bukan Disimpan 
struct queue_a {
    int a[KAP]; int front; int nef; // rear TIDAK disimpan!
};

bool QMasuk(queue_a &Q, int x) {
    if (Q.nef == KAP) return false; // PENUH
    Q.a[(Q.front + Q.nef) % KAP] = x; // RUMUS EMAS
    Q.nef++; return true;
}

bool QKeluar(queue_a &Q, int &x) {
    if (Q.nef == 0) return false;   // KOSONG
    x = Q.a[Q.front];
    Q.front = (Q.front + 1) % KAP;     // front melingkar
    Q.nef--; return true;
}

🎯 Masuk 60 Mendarat di Kotak 0:

Saat ini front = 2, nef = 3.
Indeks baru: (2 + 3) % 5 = 0!
Nilai 60 mendarat di kotak 0 yang tadi mati. Kapasitas pulih 100%!

Pembeda Penuh vs Kosong:

Saat kosong, front == rear. Saat penuh, front == rear juga! Modul ini memilih menyimpan NEF:
• Kosong jika nef == 0
• Penuh jika nef == KAP
Hasil: Nol kotak terbuang, dan rear didapat gratis!

Queue dengan Linked List: Peran Tail & 2 IF Kritis

Tanpa pointer tail, Enqueue harus menyusuri seluruh list dari awal (O(N)). Dengan tail, Enqueue seketika (O(1)).

queue_list.cpp Dua Percabangan IF Kritis 
struct queue_l {
    node_t *head; // ujung keluar (Dequeue)
    node_t *tail; // ujung masuk (Enqueue)
    int nef;
};

bool RMasuk(queue_l &Q, int x) {
    node_t *b = new node_t;
    b->data = x; b->next = nullptr;
    if (Q.head == nullptr) {
        Q.head = b; Q.tail = b; // IF KRITIS 1: queue kosong
    } else {
        Q.tail->next = b; Q.tail = b;
    }
    Q.nef++; return true;
}

bool RKeluar(queue_l &Q, int &x) {
    if (Q.head == nullptr) return false;
    node_t *b = Q.head;
    x = b->data;
    Q.head = b->next;
    if (Q.head == nullptr) Q.tail = nullptr; // IF KRITIS 2!
    delete b;
    Q.nef--; return true;
}

⚠️ IF Kritis 1: RMasuk Saat List Kosong

Saat queue kosong, baik head maupun tail wajib menunjuk node yang sama (b). Tanpa baris ini, tail->next pada operasi berikutnya akan membaca pointer liar (crash / segfault).

⚠️ IF Kritis 2: RKeluar Saat Node Terakhir Diambil

Jika node yang dihapus adalah satu-satunya elemen tersisa, head menjadi nullptr. Maka tail wajib dikembalikan ke nullptr! Tanpa baris ini, tail menjadi *dangling pointer* yang menunjuk alamat memori yang sudah di-delete.

Neraca Biaya O(1), Analisis Memori, & 6 Kesalahan Klasik

Seluruh operasi inti berjalan dalam O(1). Pilihan representasi bukan soal kecepatan komputasi.

Operasi Array Statis Linked List
Push / Enqueue O(1) (perlu modulo) O(1) (wajib tail)
Pop / Dequeue O(1) O(1)
Kapasitas Tetap (KAP) Dinamis (RAM)
Memori / Elemen 4 Byte 16 Byte (4x lipat!)

💡 Kesimpulan Strategis: Karena semua operasi inti O(1), gunakan Array Statis bila batas data pasti dan ingin hemat memori. Gunakan Linked List bila data sering tumbuh dinamis melebihi kapasitas awal.

1. Push Penuh Tulis a[KAP]. Tolak jika SPenuh.
2. Pop Kosong Baca a[-1]. Tolak jika SKosong.
3. Tanpa Modulo Kotak mati. Wajib (front+nef)%KAP.
4. Lupa Tail Awal Set head=b & tail=b saat kosong.
5. Lupa Tail Null Set tail=nullptr saat node habis.
6. Memory Leak Simpan next sebelum delete.
"Tulis pemeriksaan kondisi batas LEBIH DULU sebelum badan fungsi. Kondisi batas yang ditunda adalah kondisi batas yang terlupa."
