The Big Question • Fondasi Berpikir

"Pekan Lalu Kita Sudah Punya Array, Kenapa Pusing Bikin Linked List?"

Dua kelemahan fisik array yang tidak bisa diperbaiki oleh software engineering apa pun:

🧱

1. Kutukan Alamat Kontigu (Harus Berjejer Rapat)

Array mewajibkan seluruh elemennya bertetangga rapat di alamat memori. Konsekuensinya fatal: menyisipkan 1 data di indeks 0 pada list berisi 10.000 elemen memaksa CPU mendorong 10.000 elemen ke kanan satu demi satu ($O(N)$). Di linked list? Cukup ubah pointer head, selesai dalam 0 langkah pergeseran ($O(1)$)!

💸

2. Pajak Pemborosan & Ongkos Salin Realokasi

Kalau kapasitas array ditebak terlalu kecil $ o$ crash / harus sewa memori 2x lipat dan menyalin ulang seluruh data lama. Kalau ditebak terlalu besar $ o$ RAM mubazir tak terpakai. Linked list hanya memesan memori persis saat ada data baru masuk dan langsung mengembalikannya saat data dihapus.

💡 Analogi Ringkas: Array itu seperti ruko berjejer nomor 1 sampai 8; kalau ruko nomor 1 mau diisi toko baru, 7 toko lainnya harus gotong royong pindah sekat. Linked List itu seperti permainan cari harta karun; lokasinya bebas di mana saja di kota, tiap pos cuma mengantongi alamat pos berikutnya!

Dasar Teori 4.2.4 • Dua Struct

Dua Struct Pembawa: list_t di Stack, node_t di Heap

Pertanyaan krusial: Di mana linked list tinggal di dalam memori komputer?

1. Pengelola Rantai: struct list_t (16 Byte di Stack)

STACK

Variabel list lokal tinggal di Stack. Isinya cuma dua:

• node_t *head; (8 byte alamat ke node pertama)
• int nef; (4 byte penghitung + 4 byte padding alignment = 8 byte)

2. Gerbong Data: struct node_t (16 Byte di Heap)

HEAP

Setiap elemen data dialokasikan terpisah di Heap saat dibutuhkan via new node_t:

• int info; (4 byte muatan data asli)
• node_t *next; (8 byte penunjuk ke node berikutnya / nullptr)
definisi_linked_list.cpp Modul 4 Standar 
// Gerbong elemen di HEAP
struct node_t {
    int info;      // data (4 byte)
    node_t *next;  // alamat node berikut (8 byte)
};

// Pengendali rantai di STACK
struct list_t {
    node_t *head;  // penunjuk ke kepala (8 byte)
    int nef;       // berapa node yang hidup (4 byte)
};

// Deklarasi di main():
list_t L;
MakeEmpty(L); // L.head = nullptr, L.nef = 0
Spesifikasi Operasi • 4.2.5.1

Operasi Status Berbiaya 1 Langkah: O(1)

Empat operasi yang menanyakan atau menetapkan keadaan list tanpa perlu tahu isi satu pun node.

// 1. Inisialisasi / Kosongkan List void MakeEmpty(list_t &L) { L.head = nullptr; L.nef = 0; }
// 2. Cek Apakah List Kosong bool IsEmpty(const list_t &L) { return L.head == nullptr; }
// 3. Cek Apakah List Penuh (Selalu False!) bool IsFull(const list_t &L) { (void)L; return false; }
// 4. Jumlah Elemen Aktif int LengthIs(const list_t &L) { return L.nef; }

Kenapa IsEmpty Dicek dari Head?

Meskipun NEF harus selalu sinkron, head-lah yang memegang kebenaran mutlak. Bila head bernilai nullptr, tidak ada satu pun node yang bisa dicapai! Memeriksa dari head membuat kesalahan lupa update NEF langsung terdeteksi.

Kenapa IsFull Selalu Mengembalikan False?

Karena linked list tidak pernah penuh selama RAM komputermu masih ada sisa memori! Fungsi ini tetap wajib ada di spesifikasi agar pemakai ADT tidak dipaksa tahu representasi apa yang dipakai di dalamnya. Baris (void)L; mencegah kompilator mengeluarkan warning parameter tidak dipakai.

Pola Wajib • 4.2.5.2

Pola Penelusuran (Traversal) (Traversal)

Pada linked list tidak ada rumus alamat acak. Satu-satunya cara mencapai node ke-i adalah berjalan kaki dari depan!

pola_penelusuran.cpp Hafalkan 3 Baris Ini 
node_t *p = L.head;         // 1. Mulai dari kepala
while (p != nullptr) {       // 2. Berhenti saat habis
    cout << p->info << " ";
    p = p->next;            // 3. Maju satu langkah
}
💡 Makna p->info: Ikuti alamat yang disimpan p, lalu ambil anggota data info di alamat itu. Sama dengan (*p).info.

⚠️ Jebakan 1: while (p->next != nullptr)

Perulangannya berhenti satu langkah terlalu cepat! Node terakhir tidak pernah diproses karena begitu tiba di node ujung, loop langsung bubar. Pada list [10, 20, 30], angka 30 tidak akan pernah tercetak.

⚠️ Jebakan 2: Lupa Menulis p = p->next

Pointer p akan diam di node pertama selamanya. Syarat p != nullptr selalu benar $ o$ Infinite Loop! Program menggantung tanpa pesan apa pun.

Operasi Pencarian • 4.2.5.3

RetrieveItem & Kenapa Binary Search Mati di Sini

Mencari posisi indeks nilai x, atau mengembalikan -1 jika tidak ditemukan.

RetrieveItem.cpp Early Return 
int RetrieveItem(const list_t &L, int x) {
    int i = 0;
    for (node_t *p = L.head; p != nullptr; p = p->next) {
        if (p->info == x) return i; // Ketemu! Langsung pulang
        i++;
    }
    return -1; // Menelusuri sampai habis dan tidak ada
}
Biaya Terukur: Jika data ada di indeks $i$, biayanya $i+1$ pembandingan. Jika data tidak ada, biayanya sebanyak $NEF$ pembandingan.
☠️

Kenapa Binary Search Tidak Efisien di Linked List?

Pada array yang terurut, Binary Search bisa melompat langsung ke indeks tengah dalam 1 detik ($O(1)$) berkat rumus alamat.

Pada linked list, untuk sekadar mencapai elemen tengahnya saja kamu harus jalan kaki $N/2$ langkah dari depan! Keuntungan bagi-dua langsung musnah karena ongkos perjalanannya sendiri sudah $O(N)$.

Operasi Mahkota • 4.2.5.4

InsertFirst: Operasi Termurah & Keunggulan Mutlak

Menyisipkan elemen di posisi paling depan dalam 0 langkah pergeseran, berapa pun panjang listnya!

Aturan Emas Penyisipan:

1. Minta Memori: node_t *baru = new node_t;
2. Isi Data: baru->info = x;
3a. SAMBUNG DULU: baru->next = L.head;
Pegang tangan yang baru sebelum lepas yang lama!
3b. PINDAHKAN HEAD: L.head = baru; L.nef++;
⚡ Biaya Terukur: 0 node dilewati. Bandingkan dengan array yang harus menggeser jutaan elemen ke kanan!
InsertFirst.cpp Biaya: 0 Node 
int InsertFirst(list_t &L, int x) {
    node_t *baru = new node_t;
    baru->info = x;

    // SAMBUNG dulu ke kepala lama
    baru->next = L.head;

    // Baru alihkan kepala ke node baru
    L.head = baru;
    L.nef++;

    return 0;
}
Operasi Penyisipan • 4.2.5.6

InsertAt: Berhenti di pos - 1 & Sambung Dulu!

Menyisipkan elemen sehingga ia menempati indeks pos.

Kenapa Berhenti di pos - 1?

Karena yang akan disambungkan adalah anggota next milik pendahulunya. Kalau kamu berjalan sampai ke pos, kamu sudah terlambat dan tidak bisa mundur lagi (karena ini *singly* linked list)!

Posisi 0 tidak punya pendahulu! Langsung delegasikan: if (pos == 0) return InsertFirst(L, x);
🚨 Bencana Terbalik: Jika kamu putus dulu (p->next = baru) sebelum menyambung (baru->next = p->next), maka sisa list di kanan akan terputus dan hilang ke angkasa RAM selamanya (Memory Leak)!
InsertAt.cpp Sambung Dulu Baru Putus 
int InsertAt(list_t &L, int pos, int x) {
    if (pos < 0 || pos > L.nef) return -1;
    if (pos == 0) return InsertFirst(L, x);

    node_t *p = L.head;
    for (int i = 0; i < pos - 1; i++)
        p = p->next; // Berhenti di pos - 1

    node_t *baru = new node_t;
    baru->info = x;

    // 1. SAMBUNG dulu
    baru->next = p->next;

    // 2. Baru PUTUS
    p->next = baru;
    L.nef++;
    return 0;
}
Operasi Penyisipan • 4.2.5.5

InsertItem: Menyisipkan di Akhir Rantai

Terdengar mirip InsertFirst, tetapi ternyata jauh lebih mahal! Kenapa?

Alamat Kepala Dipegang, Alamat Ekor Tidak!

list_t hanya menyimpan pointer head. Alamat node paling akhir tidak dipegang siapa pun! Maka kita harus jalan kaki menelusuri dari kepala sampai ketemu node yang next-nya bernilai nullptr.

Syarat loop: while (p->next != nullptr)
Berhenti tepat DI node terakhir, bukan melewatinya!
⚠️ Kasus Khusus List Kosong: Bila list kosong (head == nullptr), tidak ada node yang bisa disambungi. Node baru itu sendiri langsung menjadi kepala: L.head = baru;!
InsertItem.cpp Biaya: NEF - 1 Node 
int InsertItem(list_t &L, int x) {
    node_t *baru = new node_t;
    baru->info = x;
    baru->next = nullptr; // Menjadi yang terakhir

    if (L.head == nullptr) {
        L.head = baru;
        L.nef++;
        return 0;
    }

    node_t *p = L.head;
    while (p->next != nullptr) // Berhenti DI node terakhir
        p = p->next;

    p->next = baru;
    L.nef++;
    return 0;
}
Operasi Penghapusan • 4.2.5.7

DeleteFirst & DeleteAt: Simpan Dulu, Sambung Pintas, Baru Delete!

Dua tugas mutlak: Melepaskan node dari rantai DAN mengembalikan memorinya ke sistem operasi.

DeleteFirst (Hapus Kepala)

Biaya: 0 Node 
int DeleteFirst(list_t &L) {
    if (L.head == nullptr) return -1;
    node_t *hapus = L.head;  // 1. SIMPAN dulu alamatnya
    L.head = hapus->next;    // 2. Alihkan kepala
    delete hapus;            // 3. Baru hapus!
    L.nef--;
    return 0;
}

DeleteAt (Hapus Indeks Pos)

Biaya: pos - 1 Node 
int DeleteAt(list_t &L, int pos) {
    if (L.head == nullptr || pos < 0 || pos >= L.nef) return -1;
    if (pos == 0) return DeleteFirst(L);

    node_t *p = L.head;
    for (int i = 0; i < pos - 1; i++) p = p->next;

    node_t *hapus = p->next; // 1. SIMPAN dulu
    p->next = hapus->next;   // 2. Sambung pintas melompat
    delete hapus;            // 3. Bebaskan memori
    L.nef--;
    return 0;
}
☠️ Kenapa Wajib Simpan Dulu? Karena begitu pointer pendahulu dialihkan melompat (p->next = hapus->next), tidak ada variabel yang memegang alamat node itu lagi! Kalau belum disimpan, node itu akan menjadi sampah abadi di RAM (Memory Leak).
Penyelesaian Utang Memori • 4.2.5.8

Deallocate: Membebaskan Seluruh Node Satu per Satu

Setiap new adalah utang. Pelunasannya adalah menghapus seluruh node sebelum program selesai!

Tidak Ada Jalan Pintas!

Pada array heap, satu baris delete[] a; langsung membersihkan 1.000 elemen sekaligus. Pada linked list, 1.000 node harus di-delete sebanyak 1.000 kali satu per satu!

Kesalahan Fatal: Menulis delete p; lalu p = p->next;. Itu membaca memori yang baru saja dibunuh! Kompilator menyebutnya: heap-use-after-free!
🛡️ Pola Benar: Selalu simpan penerusnya sebelum mengeksekusi delete: node_t *berikut = p->next; delete p; p = berikut;.
Deallocate.cpp Biaya: NEF kali delete 
void Deallocate(list_t &L) {
    node_t *p = L.head;
    while (p != nullptr) {
        node_t *berikut = p->next; // 1. SIMPAN dulu selagi bisa
        delete p;                  // 2. Kembalikan memori
        p = berikut;               // 3. Maju ke penerus
    }
    L.head = nullptr;              // Dinolkan kembali
    L.nef = 0;
}

Analisis Rekayasa • 4.2.6

Neraca Ongkos: Waktu vs Memori (Siapa yang Menang?)

Perbandingan nyata menyimpan 8 bilangan integer (int = 4 byte):

Operasi Array Statis Linked List
Baca elemen ke-i 1 langkah O(1) i node dilewati O(N)
Sisip di indeks 0 NEF geser O(N) 0 node dilewati O(1)!
Hapus di indeks 0 NEF - 1 geser 0 node dilewati O(1)!
Sisip di indeks i NEF - i geser i - 1 dilewati
Kapasitas habis Ditolak (-1) Tidak pernah habis!

Harga Memori untuk 8 Bilangan:

Array Statis (Stack): 36 Byte
Array Dinamis Heap: 48 Byte
Linked List: 144 Byte (4x lipat!)

Satu node_t memakan 16 byte padahal datanya cuma 4 byte: 8 byte untuk pointer dan 4 byte terbuang untuk penyelarasan (*padding alignment*).

💡 Hukum Emas Praktikum: Semakin kecil ukuran tipe elemennya, semakin mahal linked list! Tapi untuk struct besar (puluhan byte), overhead 8-byte pointer hampir tidak terasa.
Checklist Evaluasi • 4.2.7

6 Kesalahan Umum Praktikum & Checklist Kasus Uji Batas

Daftar kesalahan yang dikumpulkan dari pekerjaan mahasiswa tahun-tahun sebelumnya:

6 Kesalahan yang Sering Terjadi:

1. Baca p->info saat p bernilai nullptr: Crash seketika (Segmentation Fault)!
2. Urutan sambung dan putus terbalik: Rantai putus, list rusak atau bocor.
3. Lupa delete: Ditangkap oleh LeakSanitizer (Direct leak detected).
4. Baca p->next sesudah p dihapus: Heap-use-after-free!
5. Lupa memperbarui NEF: Listnya benar tapi LengthIs berbohong dan loop salah.
6. Curang memakai std::list: Melewatkan seluruh esensi pembelajaran wadah.

Checklist Kasus Uji Batas Wajib:

✔ List Kosong (0 node): DeleteFirst return -1, Deallocate aman.
✔ List 1 Node: Hapus node pertama membuat list jadi kosong sempurna.
✔ Sisip di indeks 0: Harus mendelegasikan ke InsertFirst.
✔ Sisip di indeks NEF: Harus sama dengan InsertItem.
✔ Hapus di indeks NEF - 1: Node terakhir terhapus, pendahulunya nullptr.
✔ Allocation Balance: Total new sama persis dengan total delete!
