The Big Question • Motivasi Belajar

"Kenapa Harus Bikin List Sendiri Kalau Sudah Ada Wadah Instan?"

Target mahasiswa semester 3: Memahami realita di balik layar sebelum menjadi pengguna buta!

🏗️

1. Menjadi Pembuat Wadah, Bukan Sekadar Konsumen

Di Python atau Java kamu tinggal panggil list.insert(). Tapi bagaimana wadah itu bekerja di memori fisik? Modul ini mengajarkan cara membangun wadah itu sendiri. Programmer biasa cuma pemakai, Software Engineer mengerti struktur dalamnya!

⏱️

2. Memahami Biaya Tersembunyi (Hidden Cost)

Menyisipkan data di awal array kelihatannya sepele (cuma 1 baris kode). Padahal CPU harus mendorong ribuan elemen ke kanan satu per satu! Menghitung biaya pergeseran ini adalah kunci utama mengapa di modul depan kita butuh Linked List.

🛡️

3. Compiler Itu Buta Terhadap Logika

Banyak mahasiswa mengira: "Kalau kode saya terkompilasi, berarti kodenya benar". SALAH BESAR! Compiler tidak tahu kalau kamu menaruh NEF di variabel global yang merusak list lain, atau salah memasang parameter. Kita belajar mencegah bug tak kasat mata.

🛑

4. Disiplin Defensive Programming

Operasi yang melanggar prasyarat (misal menyisipkan ke list penuh) WAJIB DITOLAK dengan mengembalikan nilai -1. Membiarkan operasi ilegal berjalan diam-diam adalah sumber bug tersembunyi yang sulit dilacak.

Dasar Teori 3.2.3 • Anatomi C++

Mengapa C++ Tidak Punya Fungsi Hitung Isi Array?

Pertanyaan mahasiswa: "Kenapa gak ada fungsi len(arr) di C++ biar gak usah repot catat NEF?"

1. Ilusi sizeof(a)

Pada array berukuran 8 yang baru diisi 3 elemen: sizeof(a)/sizeof(a[0]) tetap menjawab 8, bukan 3! Itu menghitung kapasitas kotak yang dipesan, bukan isi data.

2. Array Meluruh Menjadi Pointer di Fungsi

Begitu array dioper ke fungsi void coba(int arr[]), sizeof(arr) berubah menjadi 8 byte (ukuran alamat pointer di OS 64-bit).

3. Array Mentah Berisi Nilai Sampah (*Garbage*)

Menebak dari nilai juga mustahil. Array yang belum diisi berisi angka liar seperti 1651076199, 779647075, 0. Angka nol pun bisa jadi data yang sah!

bukti_memori_sampah.cpp Fakta Nyata 
int arr[8]; // belum diisi
for (int i = 0; i < 8; i++) cout << arr[i] << " ";

// Output di terminal:
0 0 10928960 32670 1651076199 779647075 73728 0
Kesimpulan Modul: NEF bukan tambal sulam untuk fitur C++ yang hilang. NEF adalah fitur itu sendiri, yang kita bangun sendiri agar komputer tahu persis mana kotak yang valid dan mana yang masih sampah!
Debat Arsitektur 1 • 3.2.2.1

Pilihan A: NEF Sebagai Variabel Global (Masalah Ketergantungan Data)

Kelihatan paling gampang dan ringkas karena parameternya pendek. Tapi inilah potensi masalah yang muncul:

Apa yang Terjadi Jika Ada 2 List?

List p diisi 3 elemen (10, 20, 30). NEF global bernilai 3. Lalu list q diisi 1 elemen (99).

p = [10, 20, 30, 32620] (memakai nef = 4)
q = [sampah, sampah, sampah, 99] (memakai nef = 4)

List q cuma diisi satu elemen, tapi angka 99 mendarat di q[3]! Kedua list rusak dan program tidak mengeluh sama sekali!

🚫 Vonis Resmi Modul: JANGAN DIPAKAI. Variabel global merusak pengujian independen dan membuat prasyarat mustahil ditegakkan!
bahaya_pilihan_a.cpp DILARANG 
int nef = 0; // satu-satunya NEF di seluruh program

int InsertItem(int elemen[], int x) {
    if (nef == KAPASITAS) return -1;
    elemen[nef] = x;
    nef++; // Siapa yang punya NEF ini? Semua list berebut!
    return 0;
}

// Di main():
int p[KAPASITAS], q[KAPASITAS];
InsertItem(p, 10); InsertItem(p, 20); InsertItem(p, 30);
InsertItem(q, 99); // 99 masuk ke q[3]!! q[0..2] berisi sampah!
Debat Arsitektur 2 • 3.2.2.2

Pilihan B: NEF Sebagai Parameter Terpisah (int &nef)

Bisa dipakai jika tidak mau pakai struct. Tapi ada cacat fatal yang tidak bisa ditangkap compiler:

Dua Hal Teknis C++:

  • • Wajib pakai tanda &: int &nef. Tanpa tanda ampersand, fungsi cuma menerima salinan, nilai di pemanggil tetap 0.
  • • Array tidak butuh tanda &: Parameter array otomatis meluruh menjadi pointer ke elemen pertama.

Cacat Fatal: Salah Pasang Parameter!

InsertItem(p, nefQ, 77); // array milik p, pencatat milik q!

Compiler tidak tahu bahwa p harus berpasangan dengan nefP. Kode salah ini tetap lolos kompilasi tanpa warning! Nilai 77 menimpa data di array p, tapi yang bertambah malah nefQ!

salah_pasang_parameter.cpp RAWAN BUG 
int InsertItem(int elemen[], int &nef, int x) {
    if (nef == KAPASITAS) return -1;
    elemen[nef] = x;
    nef++;
    return 0;
}

// Bahaya nyata di kode pemanggil:
int p[KAPASITAS], q[KAPASITAS];
int nefP = 0, nefQ = 0;

InsertItem(p, nefP, 10);
InsertItem(p, nefP, 20);

// Typo: memasangkan p dengan nefQ!
InsertItem(p, nefQ, 77); // Lolos kompilasi!!
// Hasil: p[1] tertimpa 77, nefQ jadi 1 padahal q kosong!
Solusi Resmi • 3.2.2.3

Pilihan C: NEF Menjadi Elemen dalam Struct (Pemenang Mutlak!)

Satukan array dan pencatatnya dalam satu rumah bernama record / struct.

🏆 Kenapa Pilihan C Sempurna?

  • ✔ Mustahil Salah Pasang: Tidak ada lagi 2 parameter terpisah. Array dan NEF selalu bepergian bersama dalam satu objek list_t.
  • ✔ Zero Runtime Overhead: Tidak menambah biaya eksekusi apa pun. Jumlah langkah operasi sama persis dengan Pilihan B.
  • ✔ Pass by Reference (&L): Dioper menggunakan tanda ampersand sehingga tidak ada penyalinan data yang boros memori.
Prinsip Desain: Mencegah kesalahan bukan dengan berharap programmer lebih hati-hati, melainkan dengan membuat bentuk kodenya mustahil untuk salah!
representasi_struct_resmi.cpp Standar Praktikum 2026 
const int KAPASITAS = 8;

struct list_t {
    int elemen[KAPASITAS]; // tempat menyimpan data
    int nef;               // berapa yang sedang terisi
};

int InsertItem(list_t &L, int x) {
    if (L.nef == KAPASITAS) return -1;
    L.elemen[L.nef] = x;
    L.nef++;
    return 0;
}

// Di main(): Bersih dan mustahil salah pasang!
list_t p, q;
p.nef = 0; q.nef = 0;
InsertItem(p, 10);
InsertItem(q, 99);
Spesifikasi Dale (2016) • Bagian 1

Operasi Status Berbiaya 1 Langkah: O(1)

Keempat operasi ini hanya menyentuh NEF, tidak pernah menyentuh isi array.

// 1. Mengosongkan List void MakeEmpty(list_t &L) { L.nef = 0; }
// 2. Mengecek Apakah Kosong bool IsEmpty(const list_t &L) { return L.nef == 0; }
// 3. Mengecek Apakah Penuh bool IsFull(const list_t &L) { return L.nef == KAPASITAS; }
// 4. Mengetahui Jumlah Elemen Terisi int LengthIs(const list_t &L) { return L.nef; }

Kenapa MakeEmpty Tidak Menolkan Array?

Yang menentukan ada tidaknya sebuah elemen adalah NEF, bukan isi kotaknya! Jika kamu menolkan seluruh array dengan looping, biaya operasi melonjak dari 1 langkah menjadi 8 langkah sia-sia tanpa manfaat apa pun.

Peran Kata Kunci const

Perhatikan kata const pada tiga fungsi terakhir. Operasi yang hanya membaca menyatakan dirinya tidak mengubah data. Compiler akan langsung menolak jika kita tidak sengaja menulis ke dalamnya!

Spesifikasi Dale (2016) • Bagian 2

RetrieveItem: Pencarian Linear & Jebakan Maut

Mencari indeks elemen pertama yang bernilai x, atau mengembalikan -1 jika tidak ditemukan.

RetrieveItem.cpp Dale (2016) 
int RetrieveItem(const list_t &L, int x) {
    // BATASNYA L.nef, BUKAN KAPASITAS!
    for (int i = 0; i < L.nef; i++) {
        if (L.elemen[i] == x) return i;
    }
    return -1; // Tidak ditemukan
}
⚠️ Jebakan yang Paling Sering Terjadi di Lab:
Menulis i < KAPASITAS. Program tetap terkompilasi, tetapi ikut membandingkan kotak di sebelah kanan NEF yang berisi nilai sampah/bekas hapus! Akibatnya fungsi bisa mengembalikan indeks elemen yang sudah dihapus.

Tabel Kasus & Biaya Pembandingan

Keadaan Kasus Biaya Nyata Rumus
Ketemu di indeks 2 (NEF = 4) 3 pembandingan i + 1
Nilai tidak ada (NEF = 4) 4 pembandingan NEF
Nilai tidak ada (List penuh = 8) 8 pembandingan NEF
List kosong (NEF = 0) 0 pembandingan 0
Spesifikasi Dale (2016) • Bagian 3

InsertItem (Sisip Akhir) vs InsertAt (Sisip Indeks)

Dua metode penyisipan dengan konsekuensi biaya yang sangat berbeda.

InsertItem (Akhir)

Biaya: 0 Geser

Menaruh data langsung di posisi elemen[nef]. Wajib ada penjaga if (IsFull(L)) return -1;. 

int InsertItem(list_t &L, int x) {
    if (IsFull(L)) return -1;
    L.elemen[L.nef] = x;
    L.nef++;
    return 0;
}

InsertAt (Posisi Tertentu)

Biaya: NEF - pos Geser 
int InsertAt(list_t &L, int pos, int x) {
    if (IsFull(L)) return -1;
    if (pos < 0 || pos > L.nef) return -1; // > bukan >=
    for (int i = L.nef; i > pos; i--) // DARI BELAKANG!
        L.elemen[i] = L.elemen[i-1];
    L.elemen[pos] = x;
    L.nef++; return 0;
}
🚨 Kenapa Arah Geser WAJIB dari Belakang? Karena jika digeser dari depan (i = pos; i < nef), elemen ke-1 akan menimpa elemen ke-2 sebelum sempat dipindahkan. Akibatnya, seluruh isi array rusak menjadi satu nilai kembar yang sama! Aturan emas: Selalu bergerak menjauhi elemen kosong.
Spesifikasi Dale (2016) • Bagian 4

DeleteAt (Jaga Urutan) vs DeleteUnordered (Cepat)

Dua filosofi penghapusan elemen: Menjaga kerapian antrean vs efisiensi kilat.

DeleteAt (Jaga Urutan)

Biaya: NEF - pos - 1 Geser

Geser DARI DEPAN ke kiri untuk menutup lubang. Digunakan jika urutan data memiliki arti penting (misal: antrean nasabah bank). 

int DeleteAt(list_t &L, int pos) {
    if (IsEmpty(L)) return -1;
    if (pos < 0 || pos >= L.nef) return -1;
    for (int i = pos; i < L.nef - 1; i++) // DARI DEPAN
        L.elemen[i] = L.elemen[i+1];
    L.nef--; return 0;
}

DeleteUnordered (Tanpa Urutan)

Biaya: 0 Geser!

Ambil elemen terakhir (elemen[nef-1]), tancapkan langsung ke posisi lubang! Super cepat, tapi mengacak urutan. 

int DeleteUnordered(list_t &L, int pos) {
    if (IsEmpty(L)) return -1;
    if (pos < 0 || pos >= L.nef) return -1;
    L.elemen[pos] = L.elemen[L.nef - 1]; // Tutup langsung
    L.nef--; return 0;
}
💡 Kapan Boleh DeleteUnordered? Hanya bila urutan tidak dijanjikan oleh spesifikasi (contoh: keranjang belanja, kumpulan ID kartu). Pada daftar yang urutannya bermakna (jadwal kuliah, ranking), fungsi ini merusak integritas data!

Analisis Algoritmik • 3.2.5

Rangkuman Biaya Operasi & Jembatan ke Linked List

Tabel terukur ini adalah alasan mengapa kita tidak bisa mengandalkan array untuk semua masalah:

Operasi Biaya pada NEF = 8 Langkah Nyata
MakeEmpty, IsEmpty, IsFull, LengthIs 1 langkah 1
Baca elemen ke-i (Akses Acak) 1 langkah 1
InsertItem (Sisip Akhir) 0 pergeseran 0
DeleteUnordered (Tanpa Urutan) 0 pergeseran 0
RetrieveItem (Pencarian) sampai NEF banding 8
InsertAt indeks 0 NEF - i geser 7 pergeseran
DeleteAt indeks 0 NEF - i - 1 geser 7 pergeseran

Keunggulan Array:

Array sangat sakti untuk membaca elemen acak via indeks (elemen[i] hanya 1 langkah $O(1)$) dan menambah elemen di ujung ($O(1)$).

Kelemahan Fatal Array:

Array sangat mahal dan lambat ketika harus disisipi atau dihapus di tengah/depan karena seluruh tetangganya harus didorong satu-satu ($O(N)$).

Checklist Evaluasi • 3.2.6

5 Kesalahan yang Wajib Dihindari & Uji Kondisi Batas

Daftar kesalahan yang sering terjadi saat praktikum:

5 Kesalahan yang Sering Terjadi:

a. Fungsi int tanpa return di semua jalur: Kompilator -O0 mati crash, di -O2 loop selamanya. Wajib return -1!
b. Variable Length Array (int arr[n]): Bukan C++ baku. Wajib konstanta: const int KAPASITAS = 8;.
c. Array dan NEF dibiarkan terpisah: Menimbulkan bug salah pasang parameter tanpa warning.
d. Batas perulangan memakai KAPASITAS: Seharusnya i < L.nef.
e. Memakai wadah pustaka standar: Dilarang memakai std::vector.

Checklist Kasus Uji Batas Wajib:

✔ List Kosong (NEF = 0): DeleteAt dan RetrieveItem wajib return -1.
✔ List Penuh (NEF = 8): InsertItem dan InsertAt wajib ditolak return -1.
✔ Sisip di indeks 0: Geser maksimum (NEF geser).
✔ Sisip di indeks NEF: Geser minimum (0 geser).
✔ Hapus di indeks 0: Geser maksimum (NEF - 1 geser).
✔ Hapus di indeks NEF - 1: Geser minimum (0 geser).
